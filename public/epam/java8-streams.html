The 12 Streams questions from the EPAM prep guide, each with an approach, working code, real output, complexity, and the follow-ups interviewers usually ask. Everything was compiled with javac --release 8 and run, and each output shown here is copied from that run. The full runnable file is StreamsPrep.java. ← Back to the tracker

00

Shared setup

Questions 4, 5, 6, 10 and 12 use this data. It's a plain class with getters, not a record: records arrived in Java 16, and the interview says Java 8.

import java.util.*;
import java.util.function.*;
import java.util.stream.*;

class Employee {
    private final String name, dept;
    private final double salary;
    Employee(String name, String dept, double salary) {
        this.name = name; this.dept = dept; this.salary = salary;
    }
    String getName()   { return name; }
    String getDept()   { return dept; }
    double getSalary() { return salary; }
}

List<Employee> employees = Arrays.asList(
    new Employee("Asha",  "Engineering", 120000),
    new Employee("Ravi",  "Engineering",  95000),
    new Employee("Meera", "HR",           60000),
    new Employee("Karan", "Sales",        70000),
    new Employee("Divya", "Engineering", 135000),
    new Employee("Arjun", "HR",           65000),
    new Employee("Neha",  "Sales",        82000));
Java 8 vs newer: what to avoid writing in a "Java 8" interview
  • stream.toList() is Java 16. Use collect(Collectors.toList()).
  • List.of(...) and Map.of(...) are Java 9. Use Arrays.asList(...) or Collections.emptyList().
  • String.isBlank() is Java 11. Use trim().isEmpty().
  • Optional.isEmpty() is Java 11. Use !isPresent(). Optional.orElseThrow() with no argument is Java 10.
  • Collectors.teeing is Java 12. takeWhile/dropWhile are Java 9.
  • If they allow modern Java, say so and use the shorter forms. Knowing the difference is the signal.
01

Second-highest number in a list

Remove duplicates first, sort descending, skip the largest, then take the next one. Return an Optional, because the list may have fewer than two distinct values.

List<Integer> nums = Arrays.asList(5, 9, 2, 9, 7, 5);

Optional<Integer> second = nums.stream()
        .distinct()
        .sorted(Comparator.reverseOrder())
        .skip(1)
        .findFirst();
Output
Optional[7]
Complexity

O(n log n) time, O(n) space.

Interview notes
  • Without distinct(), [5, 9, 9] would give 9. That's the classic bug interviewers watch for.
  • [7, 7] or an empty list → Optional.empty. Say this edge case out loud.
  • Follow-up "do it in O(n)": one pass with two variables (first, second), no stream needed.
  • Same pattern for Nth highest: skip(n - 1).
02

Duplicate elements in a list

Two standard answers. (a) A HashSet whose add() returns false for a repeat. It's short, but the lambda has a side effect. (b) Count with groupingBy and keep the keys whose count is above 1. It's pure, and the one to lead with.

List<Integer> list = Arrays.asList(1, 4, 2, 4, 3, 1, 4);

// (a) Set.add trick: short, but stateful (not safe with parallel streams)
Set<Integer> seen = new HashSet<>();
List<Integer> dupsA = list.stream()
        .filter(n -> !seen.add(n))
        .distinct()
        .collect(Collectors.toList());          // [4, 1]  (order of the 2nd occurrence)

// (b) count then filter: side-effect free
Set<Integer> dupsB = list.stream()
        .collect(Collectors.groupingBy(Function.identity(),
                 LinkedHashMap::new, Collectors.counting()))
        .entrySet().stream()
        .filter(e -> e.getValue() > 1)
        .map(Map.Entry::getKey)
        .collect(Collectors.toCollection(LinkedHashSet::new));   // [1, 4]
Output
[4, 1]   (a)
[1, 4]   (b)
Complexity

O(n) time, O(n) space for both.

Interview notes
  • Expect the question: why is (a) risky? Stateful lambdas break with parallel(), and the Stream API docs advise against them.
  • LinkedHashMap::new keeps first-seen order. A plain groupingBy returns a HashMap with no defined order.
  • Collections.frequency(list, x) > 1 inside a filter also works, but it's O(n²). Mention it as the brute force.
03

Frequency of each character in a string

String.chars() gives an IntStream. Box each value to Character, then group by identity and count.

String s = "programming";

Map<Character, Long> freq = s.chars()
        .mapToObj(c -> (char) c)
        .collect(Collectors.groupingBy(Function.identity(),
                 LinkedHashMap::new, Collectors.counting()));
Output
{p=1, r=2, o=1, g=2, a=1, m=2, i=1, n=1}
Complexity

O(n) time, O(k) space (k = distinct characters).

Interview notes
  • counting() returns Long, not Integer. For Integer, use Collectors.summingInt(c -> 1).
  • Case-insensitive: add .map(Character::toLowerCase). To skip spaces: .filter(c -> c != ' ').
  • Without streams, an int[26] or int[128] array is faster. Worth mentioning.
04

Group employees by department

groupingBy with a downstream collector. mapping() keeps just the names instead of whole objects. TreeMap::new sorts the departments.

Map<String, List<String>> byDept = employees.stream()
        .collect(Collectors.groupingBy(Employee::getDept,
                 TreeMap::new,
                 Collectors.mapping(Employee::getName, Collectors.toList())));

// simplest form (values are List<Employee>):
// employees.stream().collect(Collectors.groupingBy(Employee::getDept));
Output
{Engineering=[Asha, Ravi, Divya], HR=[Meera, Arjun], Sales=[Karan, Neha]}
Complexity

O(n) time with a HashMap, O(n log d) with a TreeMap.

Interview notes
  • Know the three overloads: groupingBy(f), groupingBy(f, downstream), groupingBy(f, mapFactory, downstream).
  • Count per department: groupingBy(Employee::getDept, counting()).
  • Average salary per department: groupingBy(Employee::getDept, averagingDouble(Employee::getSalary)).
05

Highest-paid employee in each department

Two ways. groupingBy + maxBy gives Optional<Employee> values, which is awkward. toMap with a merge function that keeps the higher salary gives plain Employee values. Lead with toMap.

Comparator<Employee> bySalary = Comparator.comparingDouble(Employee::getSalary);

// (a) toMap + merge function: values are Employee, not Optional
Map<String, Employee> top = employees.stream()
        .collect(Collectors.toMap(Employee::getDept,
                 Function.identity(),
                 BinaryOperator.maxBy(bySalary),
                 TreeMap::new));

// (b) groupingBy + maxBy: values are Optional<Employee>
Map<String, Optional<Employee>> top2 = employees.stream()
        .collect(Collectors.groupingBy(Employee::getDept,
                 Collectors.maxBy(bySalary)));

// (c) groupingBy + collectingAndThen to unwrap the Optional
Map<String, Employee> top3 = employees.stream()
        .collect(Collectors.groupingBy(Employee::getDept,
                 Collectors.collectingAndThen(
                     Collectors.maxBy(bySalary), Optional::get)));
Output
Engineering -> Divya
HR -> Arjun
Sales -> Neha
Complexity

O(n) time, O(d) space.

Interview notes
  • toMap without a merge function throws IllegalStateException: Duplicate key once a key repeats. A common trap.
  • Optional::get in (c) is safe because a group always has at least one element.
  • Ties: maxBy keeps the first of equal elements. If they ask, add .thenComparing(...).
06

Sort employees by salary, descending

Comparator.comparingDouble(...).reversed(). Add a tie-breaker with thenComparing.

List<String> sorted = employees.stream()
        .sorted(Comparator.comparingDouble(Employee::getSalary).reversed()
                          .thenComparing(Employee::getName))
        .map(Employee::getName)
        .collect(Collectors.toList());
Output
[Divya, Asha, Ravi, Neha, Karan, Arjun, Meera]
Complexity

O(n log n) time.

Interview notes
  • Trap: reversed() reverses the whole chain built so far. comparing(a).thenComparing(b).reversed() reverses both keys.
  • To reverse a single key: thenComparing(Employee::getName, Comparator.reverseOrder()).
  • comparingDouble avoids boxing. Comparator.comparing(Employee::getSalary) also works, with boxing.
07

First non-repeating character

Count with a LinkedHashMap, which keeps insertion order, then return the first entry with count 1.

String word = "swiss";

Optional<Character> firstUnique = word.chars()
        .mapToObj(c -> (char) c)
        .collect(Collectors.groupingBy(Function.identity(),
                 LinkedHashMap::new, Collectors.counting()))
        .entrySet().stream()
        .filter(e -> e.getValue() == 1L)
        .map(Map.Entry::getKey)
        .findFirst();
Output
Optional[w]
Complexity

O(n) time, O(k) space.

Interview notes
  • With a plain HashMap the answer is unpredictable. Explain why you chose LinkedHashMap. That's what they're testing.
  • First repeating character (from the DSA list) uses the Set trick instead: chars().mapToObj(c -> (char) c).filter(c -> !seen.add(c)).findFirst() → 's' for "swiss".
  • e.getValue() == 1L: the value is a Long, and the comparison unboxes it, so it's correct.
08

Convert a list of lists into a single list

flatMap turns each inner list into a stream and concatenates them.

List<List<Integer>> nested = Arrays.asList(
        Arrays.asList(1, 2), Arrays.asList(3),
        Collections.emptyList(), Arrays.asList(4, 5));

List<Integer> flat = nested.stream()
        .flatMap(List::stream)
        .collect(Collectors.toList());
Output
[1, 2, 3, 4, 5]
Complexity

O(total elements).

Interview notes
  • Explain the difference: map is one-to-one (you'd get Stream<List<Integer>>), while flatMap is one-to-many and flattens.
  • Empty inner lists are skipped. Null inner lists throw an NPE. Guard with .filter(Objects::nonNull).
  • Variant: all unique skills of all employees → flatMap(e -> e.getSkills().stream()).distinct().
09

Partition numbers into even and odd

partitioningBy takes a predicate and always returns a map with both keys, true and false.

Map<Boolean, List<Integer>> evenOdd = IntStream.rangeClosed(1, 10)
        .boxed()
        .collect(Collectors.partitioningBy(n -> n % 2 == 0));

List<Integer> even = evenOdd.get(true);
List<Integer> odd  = evenOdd.get(false);
Output
even=[2, 4, 6, 8, 10]
odd=[1, 3, 5, 7, 9]
Complexity

O(n).

Interview notes
  • partitioningBy vs groupingBy: partitioning always has both keys, even when one list is empty. groupingBy only has keys that occur.
  • boxed() is needed because IntStream has no collect(Collector).
  • Negative numbers: -3 % 2 == -1, so test n % 2 == 0 for even, never n % 2 == 1 for odd.
10

Top 3 highest-paid employees

Sort descending by salary, then limit(3).

List<String> top3 = employees.stream()
        .sorted(Comparator.comparingDouble(Employee::getSalary).reversed())
        .limit(3)
        .map(Employee::getName)
        .collect(Collectors.toList());
Output
[Divya, Asha, Ravi]
Complexity

O(n log n). With a size-k min-heap: O(n log k).

Interview notes
  • Follow-up "what if n is huge?": a PriorityQueue of size k gives O(n log k). That links to Kth Largest Element (LC 215) from the DSA list.
  • Top 3 per department: groupingBy(dept, collectingAndThen(toList(), l -> l.stream().sorted(...).limit(3).collect(toList()))).
  • Distinct salaries only (ignoring ties): map to salary, distinct(), sort, limit(3).
11

Most frequent word in a list of sentences

Split each sentence into words with flatMap, lowercase them, count with groupingBy, then take the entry with the highest count.

List<String> sentences = Arrays.asList(
        "the cat sat", "The dog sat down", "the cat and the dog");

Optional<Map.Entry<String, Long>> top = sentences.stream()
        .flatMap(line -> Arrays.stream(line.toLowerCase().split("\\W+")))
        .filter(w -> !w.isEmpty())
        .collect(Collectors.groupingBy(Function.identity(), Collectors.counting()))
        .entrySet().stream()
        .max(Map.Entry.<String, Long>comparingByValue()
             .thenComparing(Map.Entry.comparingByKey(Comparator.reverseOrder())));
Output
Optional[the=4]
Complexity

O(total words) time, O(distinct words) space.

Interview notes
  • split("\\W+") splits on punctuation as well as spaces. A leading separator produces an empty first token, hence the filter.
  • Ties: comparingByKey(reverseOrder()) inside max picks the alphabetically smallest word. Say which tie rule you're using.
  • Map.Entry.<String, Long>comparingByValue() needs the explicit type witness because thenComparing is chained after it.
12

Sum of salaries by department

groupingBy with summingDouble as the downstream collector.

Map<String, Double> total = employees.stream()
        .collect(Collectors.groupingBy(Employee::getDept,
                 TreeMap::new,
                 Collectors.summingDouble(Employee::getSalary)));
Output
{Engineering=350000.0, HR=125000.0, Sales=152000.0}
Complexity

O(n).

Interview notes
  • All the stats in one pass: summarizingDouble(Employee::getSalary) gives count, sum, min, average and max.
  • Real code uses BigDecimal for money. Then use reducing(BigDecimal.ZERO, Employee::getSalary, BigDecimal::add). Saying this is a good senior-level signal.
  • Department with the highest total: stream the result map's entrySet() and call max(Map.Entry.comparingByValue()).
★

Collectors cheat sheet

filter / map / flatMapTransform the stream: filter keeps some elements, map converts one to one, flatMap one to many.
distinct / sorted / skip / limitDrop duplicates, order, and slice.
findFirst / anyMatch / max / countTerminal: returns an Optional, boolean or long.
groupingBy(f, factory, downstream)Map<K, R>: buckets elements by key.
partitioningBy(pred)Map<Boolean, List>: always has both keys.
toMap(k, v, merge, factory)Throws on a duplicate key unless you pass merge.
counting / summingX / averagingXNumeric downstream collectors.
mapping / maxBy / collectingAndThenReshape or unwrap each group.
joining(", ", "[", "]")Join strings with a separator, prefix and suffix.
IntStream.range / chars / boxedPrimitive streams: call boxed() before collect.
Concepts they may ask about alongside these
  • Lazy evaluation: intermediate operations run only when a terminal operation is called. A stream can be consumed only once.
  • Stateless vs stateful operations: sorted and distinct buffer elements. limit and findFirst short-circuit.
  • Parallel streams: use them only for large, CPU-bound, side-effect-free work. They run on the common ForkJoinPool.
  • Functional interfaces: Predicate, Function, Consumer, Supplier, BiFunction, UnaryOperator, BinaryOperator.
  • Optional: use it for return values, not for fields or parameters. Prefer map/orElse over get().
